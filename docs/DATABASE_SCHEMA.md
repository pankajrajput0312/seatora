# Database Schema (conceptual)

Implemented so far in `prisma/schema.prisma`: **DataSource, College, Specialty, CollegeSpecialty, Cutoff, Allotment, CollegeTerm, ClinicalFacts, FeesStructured, Announcement, Resident, HiddenResident, ResidentsRead, RetiredCollegeKey, WaitlistEntry** (landing-page early access), **User, Session, PasswordReset** (email/password auth; PasswordReset: a one-time reset link's token hash, `userId`, `expiresAt`, see docs/ARCHITECTURE.md), **FunnelEvent, ErrorGroup** (docs/FUNNEL.md). The other entities are documented here and added when real source data for them has been examined. Do not model data you have not seen.

## Provenance
Every factual record references a `DataSource` and carries `lastVerifiedAt` and `verificationStatus`. Rules are in [DATA_INTEGRITY.md](DATA_INTEGRITY.md).

## Entities

| Entity | Purpose | Key relationships |
|---|---|---|
| **User** | Account identity: email, name, password hash, `role` (OWNER / ADMIN / PREMIUM / FREE), `premiumUntil` | 1–1 StudentProfile; 1–n SavedCollege, CollegeComparison, CollegeReview |
| **StudentProfile** | Rank, category, domicile state, preferences | belongs to User |
| **College** | Institute: name, slug, city, state, PIN, address (as printed by MCC; null when only a short name was printed); bundle schema 2: `mccIds` (every MCC institute id the seat PDFs print for it), `mccProfileUrl` (its main id's MCC profile), `type` + `typeBasis` (govt / private / trust / deemed / central / esic / municipal / armed_forces / psu / railway, inferred by the exporter from name and quota: not an official field, the basis says how), `website` (as its own MCC profile declares it, "www.…") | 1–n CollegeSpecialty, FeeStructure, Stipend, BondInformation, CollegeReview |
| **Specialty** | A course: degree (MD/MS/DNB/Diploma/NBEMS Diploma…) + discipline; `code` is the discipline shared across degrees (e.g. `ANAESTHESIOLOGY` for MD, DNB and Diploma), set by the importer | 1–n CollegeSpecialty |
| **CollegeSpecialty** | A specialty offered at a college (join) | 1–n SeatMatrix, Cutoff, Allotment |
| **SeatMatrix** | Seats per counselling year, round, quota and category | belongs to CollegeSpecialty; DataSource |
| **Cutoff** | Opening and closing rank per year, round, quota and category | belongs to CollegeSpecialty; DataSource |
| **Allotment** | One seat allotment as printed in an MCC result: year, round, rank, quota, seat category, status (`allotted` / `fresh` / `upgraded`); bundle schema 2: `candidateCategory` (the candidate's own category as printed, not the seat's), `optionNo` (choice number, R2/R3 only), the seat printed in the previous round's columns (`prevCollegeId`, `prevSpecialtyId`, `prevQuota`, `prevRemark` reported / not_reported / seat_surrendered / seat_cancelled; R2/R3, null where the PDF prints "-"). Rank and seat only, never a name or roll number | belongs to CollegeSpecialty; DataSource; previous seat: College, Specialty (set null) |
| **ClinicalFacts** | One per college (`collegeId` key): self-reported beds, OPD/IPD, equipment, per-course accreditation and trainee record, disclosed stipend (`data` JSONB, every value with its `values_meta` source, period, check date and flags), NBEMS disclosure `disclosureStatus` / `disclosureUrl` / `checkedAt`. Raw SQL like `CollegeTerm.details` | belongs to College (cascade) |
| **FeesStructured** | Fee and stipend per course year, bond, leaving penalty and MCC forfeit per college × programme (MD/MS, Diploma, DNB, NBEMS Diploma) × seat-type group (`quotaGroup`: All India, Deemed/Paid, NRI, DNB Quota, merged groups joined by "+"), `data` JSONB with numbered sources. `fee_display` "verbatim" (or absent) = show the profile's words (`fee_text`), and figures only from `fee_parsed` (each with its quote; checked on import to be inside `fee_text`). Raw SQL | belongs to College (cascade) |
| **FeeStructure** | Tuition and other fees per academic year and quota | belongs to College (optionally Specialty); DataSource |
| **Stipend** | Monthly stipend per year of residency | belongs to College; DataSource |
| **BondInformation** | Service bond years, penalty amount, conditions | belongs to College (often state-level); DataSource |
| **CollegeReview** | Resident or alumni experience by category (academics, clinical exposure, faculty, patient load, work-life, hostel) | belongs to College and User; moderation status |
| **CollegeTerm** | Fee, stipend, bond or penalty text exactly as published, per college and program (MD/DNB); `amountInr`: FEE/STIPEND the text's one rupee figure, BOND what a non-service All India candidate pays for a PG degree (0 = no bond), PENALTY the leaving penalty else the forfeit; `details` (JSONB): the verified record, required on every BOND and PENALTY and never on FEE/STIPEND (the importer rejects either way round; a schema 2 FEE/STIPEND must have FeesStructured records for its college + program (stored there only, the catalog attaching them back; an older export's `details.records` must equal them)), written and read with raw SQL so a generated client without the field still works. An unknown bond with no document is imported with its words, its DataSource the bond check (`seatora/bond-check`, no URL, Third-party research) | belongs to College; DataSource |
| **Resident** | A name on an MCC admitted-candidates list: year, name, list label, rank (nullable: All India Rank from that year's NBEMS NEET PG result, 2023-2025) and `rankBasis` (that result, a `DataSource.key`), `match` (how the bundle matched rank + college + course to an allotment), `quota` and `round` (only when `match` = "matched"), `sourceKey` (the list PDF = `DataSource.key`), `hidden` (set from HiddenResident on import). No reservation category. No roll numbers or contact details | belongs to College (cascade) and Specialty |
| **HiddenResident** | A person who asked to be hidden: `name` + `place` (the college's PIN code, or its key without one), so the hide survives both imports, a new college key and a course change (the MCC import copies hides to a college's new place whenever it changes: a kept college given a PIN, or a retired college's successor elsewhere) | none (no foreign key on purpose) |
| **ResidentsRead** | No longer written (plans count residents reads in `UsageDaily`); kept one release so the previous deploy keeps working mid-rollout, then dropped | none |
| **UsageDaily** | Counted uses per account (or device: `userId` = `aid:<seatora_aid>`, the Free plan's per-device count), IST day and feature (`ask`, `residents`): `count`, primary key (userId, day, feature); one atomic upsert that stops at the plan's limit (`features/plans/usage.ts`) | none (no foreign key: counters only) |
| **UsageDistinct** | Distinct things opened per account (or device, as above), IST day and feature (`institutes`: `key` = College.key), primary key (userId, day, feature, key); insert-ignore, then count | none |
| **ReferralEarning** | 20% of a referred payment owed to the referrer: `referrerId`, `paymentId` (unique), `buyerId`, `amount` (paise), `status` (pending / paid_out / void, CHECK), `createdAt`, `paidOutAt`, `note`; index (referrerId) | n–1 User (referrer, cascade), 1–1 Payment (cascade) |
| **FunnelEvent** | A first-party funnel event (docs/FUNNEL.md): `at`, `name` (lib.ts `EVENTS`), `aid` (device cookie), `userId` (FK SET NULL), `placement` (where an Upgrade was clicked), `meta` (JSON, small, never personal); indexes (name, at), (userId), (aid). Kept 12 months | User (optional) |
| **ErrorGroup** | Server and browser errors grouped by `fingerprint` (the key: sha1 of kind, route and the message without ids or numbers): `kind` (server / client_error), `message` (scrubbed, ≤ 500), `route` (no query), `count`, `firstAt`, `lastAt`, `lastDigest`, `resolvedAt` (cleared by a new occurrence) | none |
| **Coupon** | A Season Pass coupon (docs/PAYMENTS.md "Coupons"): `code` (unique, CHECK A–Z 0–9, 3–20), `percentOff` (CHECK 1–100), `active`, `maxUses` (null = no limit), `uses`, `allowedEmail` (lowercase CHECK; null = anyone), `validUntil`, `note`, `createdAt` | has CouponRedemptions and Payments |
| **CouponRedemption** | One account's use of a coupon: `couponId`, `userId`, `paymentId` (unique), `createdAt`; unique (couponId, userId), index (userId) | n–1 Coupon (cascade), n–1 User (cascade), 1–1 Payment (SET NULL) |
| **AdminAudit** | A change made on `/decide/admin`: `actorId`, `targetId`, `action`, `before`, `after` (JSON), `createdAt`; index (targetId, createdAt) | none (kept if either account is deleted) |
| **RetiredCollegeKey** | A college key an MCC import retired (bundle `key_aliases.json`: merged into another college, or a name replaced by a neutral label): `oldKey` (or `sha256:<hex>` of it where the key held a person's name or e-mail), `oldSlug` (the college's slug when the import removed it, hashed the same way; null when this database never had it), `newKey` (null: gone). Kept across imports (upserted; an older row follows its college to the current key); raw SQL like `CollegeTerm.details` | none (no foreign key: the import keeps `newKey` current) |
| **Announcement** | Counselling notice: authority, category, year, date, official URL | DataSource |
| **DataSource** | Where data came from: name, URL, type (trust tier), publication date | referenced by all factual records |
| **DataVerification** | Audit trail: who verified which record, when, and the outcome | polymorphic (recordType + recordId) |
| **SavedCollege** | A user's shortlisted college with order and notes | User × College |
| **CollegeComparison** | A saved set of colleges (and an optional specialty) to compare | belongs to User; n–n College |

## Notes and open questions
- `Cutoff.quota` and `Cutoff.category` are strings holding the MCC labels verbatim (quota: "All India", "DNB Quota", "Deemed/Paid Seats"…; category: "Open", "OBC", "SC", "ST", "EWS", "<X> PwD"). State counselling labels will differ; do not map them onto MCC ones.

## MCC import (`npm run db:import`)
Source: the neetpg-planner export (`python3 -I tools/export_medpath.py` → `data/medpath-r3/`, schema 2; `data/medpath/` is schema 1), built from MCC allotment result PDFs. Aggregates only; candidate category and option number are per rank, never with a name; the bundle never contains candidate names, roll numbers or application ids, and the Zod schemas (`src/features/cutoffs/lib/import-schema.ts`) are `.strict()` so an extra field aborts the import.
- **closingRank / openingRank**: worst / best NEET PG All India Rank allotted in that round for that college, course, quota and **seat category** (the category of the seat, not of the candidate — an Open seat can go to an OBC candidate).
- **n**: allotments made in that round. In R2, R3 and stray rounds it counts only new or upgraded allotments. It is **not** the seat matrix; never show it as "seats".
- **Provisional rounds**: `DataSource.provisional = true` (e.g. 2026 R1 from the provisional result). Their cutoffs are `verificationStatus = PENDING` and must be labelled provisional in the UI. When the final result for the same year and round is imported, the provisional source's cutoffs are deleted.
- `DataSource.key` (the source PDF path, or the URL for fee/stipend documents) and `College.key` (40 name letters + `#` + PIN) are the stable import keys. College `city` is null: the source does not give it and it is never guessed; `type` is the exporter's inference (schema 2, with `typeBasis`), null from a schema 1 bundle. A college slug is set once on creation and not changed on re-import. Keys the bundle retired (`key_aliases.json`, checked: each once, none still a key, each pointing at a college the bundle has) go into `RetiredCollegeKey` with the slug their college had, so `/decide/institutes/<old slug>` and `/api/v1/colleges/<old slug>…` answer 308 to the college's slug now, and option ids saved in a browser are renamed (`/api/v1/retired-keys`). The import reports `retiredKeys` (rows, slugs, what it found under retired keys and now has under the new ones: colleges, cutoffs, allotments, seat lines, residents; hides copied).
- Cutoffs and allotments are replaced source by source in one transaction per source (delete by `sourceId`, then insert). Re-running the import with the same bundle is safe.
- **Allotment** rows are the rank-level data behind the cutoffs: per cell (college, course, year, round, quota, seat category) their count equals `Cutoff.n` and their best/worst rank equal `openingRank`/`closingRank`; the importer checks this before writing. `status` is MCC's remark normalised: `allotted` (R1, stray rounds), `fresh` or `upgraded` (R2, R3). The UI shows `upgraded` as "Upgraded" and the others as "Fresh". Indexes: (year, rank) for rank scans, (collegeSpecialty, year, round) for an institute's course, (source) for replacement.
- Before committing, the importer re-asserts known values and rolls back on any failure; among them, every virtual vacancy row of the newest round must have an allotment in an earlier round of that year on its own college, course, quota and seat category (it is a seat someone holds), which catches one institute split under two keys.
- **Bundle schema 2** (`data/medpath-r3`, the default; schema 1 still imports, leaving the schema 2 columns null / empty and the two tables empty): every allotment's previous seat must be that rank's allotment one round back (R1 for R2, R2 for R3; rank = one candidate per year and round), in the file and again in the database before commit, plus one known journey (2023 rank 23); an option number only in R2/R3; clinical facts once per college, every value with its `values_meta` entry and every entry with a value; fee records once per college × programme × seat group, every cited `src` in the record's `sources`, a verbatim record with no fee figures. Written with raw SQL (the shared generated client predates these columns); allotment ids are `gen_random_uuid()`.
- Rows whose MCC course text could not be split into degree and specialty (e.g. "MD/MS (Anatomy)") are excluded by the exporter and counted in its `manifest.json`.
- Fees can be per course, per year or a lump sum. Model `FeeStructure` after reviewing actual fee notifications.
- Bond terms are often defined by the state rather than the college. Confirm before modelling.
- Reviews need a verification design (for example proof of enrolment) before any review can be labelled verified.

## Exams (`exam` columns, `CollegeExam`; `src/features/exams`)
- Every dataset table has `exam` (default `neet-pg`, so every row from before is NEET PG's): DataSource, Specialty, Cutoff, Allotment, CollegeTerm, FeesStructured, ClinicalFacts, Announcement, RoundStep, MeritList, ScoreRank, MeritPosition. CollegeSpecialty belongs to its Specialty's exam, SeatSource and SeatCount to their DataSource's. Keys are per exam: DataSource (exam, key), Specialty (exam, slug), CollegeTerm (exam, college, program, kind), MeritList (exam, year) and the RoundStep, ScoreRank, MeritPosition, ClinicalFacts and FeesStructured primary keys. Resident has none: residents are NEET PG's.
- **College** is shared: one row per institute, same key rule in every bundle. `CollegeExam` says which exams' bundles have it. NEET PG's import writes the fields of every college it has; another exam's import only creates a college no exam has yet and never changes an existing row (it adds its `CollegeExam` row). A college goes only when no exam has it; one an exam drops but another keeps loses that exam's row (and takes the other exam's earliest result PDF as `sourceId` if its own was the dropping exam's).
- Another exam's allotments may have no `option_no` in R2 / R3 (NEET MDS mop-up 2019, 2020, 2022) and no `candidate_category` (NEET SS) where its PDFs print none; NEET PG's must have both. NEET SS ranks are per question group (`keys.ts` `ranksPerGroup`; the group rides in the quota label), so the importer takes a candidate as a rank within a quota, and a previous seat of one who moved group need only be a seat allotted one round back.
- `npm run db:import -- --exam <key> <bundle>` (else `manifest.exam`, schema 3, else `neet-pg`) replaces only that exam's rows, in one transaction; its data version is its own marker (`import/mcc` for NEET PG, `import/<exam>` otherwise). Another exam's bundle needs only sources, colleges, courses, cutoffs and allotments; NEET PG's still needs every file, and only NEET PG's import runs the NEET PG spot checks (the generic ones run for all). The build's catalog snapshot is NEET PG's alone, and its fingerprint counts only NEET PG's colleges, so importing another exam never forces a rebuild.

## Residents import (`npm run db:import-residents`)
Source: the PRIVATE neetpg-planner bundle `data/medpath-private/` (`residents.ndjson` + `manifest.json`), read from that path or `RESIDENTS_BUNDLE`, never copied into this repo. Run after `npm run db:import`.
- Each row is validated with a `.strict()` Zod schema (any extra field, e.g. a roll number, aborts); the file's sha256 and row count must match the manifest. `src` must be `mcc/<year>/<list>.pdf`. A rank needs a `rank_basis` of the same year (`nbems/<year>/...`) listed in the manifest's `rank_sources` (`{ key, name, url, year }`, the official URL without the planner's `#sha256=` pin), upserted in the replace-all transaction as `DataSource` rows (no round, `provisional` false) so the Residents Sources link them (a key the MCC import also writes, the 2025 merit list, keeps the name of whichever import ran last). A bundle without `rank_sources` (older) imports only while it has no ranks outside 2025.
- College by `ikey` = `College.key`, course by degree + `Specialty.code` (as `import-mcc.ts` maps them). Rows with an unknown college or course, or a quota the MCC import never stored, are rejected and listed, never guessed. `rank_basis`, `match`, `quota`, `round` are optional (an older bundle imports them as null); quota and round only with `match` "matched", and rank, `rank_basis` and `match` != "no_rank" go together.
- Replace-all in one transaction. `hidden` is set from `HiddenResident` by (name, college PIN code), never from the rows being replaced (an MCC import that changes a college key or course cascades those away first and reports them as `removed.residents`), so a name someone asked to hide stays hidden. Unhiding is a manual database change: delete the `HiddenResident` row and re-import.
- One `DataSource` per list PDF (key = `sourceKey`, official URL from the planner's `data/official_sources.json`, `round` null so the Decide catalog never counts it as an allotment result).
- Indexes: (collegeId, year) for an institute's tab, (specialtyId), (year, rank) for Residents across colleges; plans migration: a pg_trgm GIN on `name` (the search's `ILIKE '%token%'`, with the token's colleges looked up first), (name, year DESC, id) for the name sort, (hidden, year) for the Year filter's years. Timings in PLANS_AND_ROLES.md.

## Feature requests (`FeatureRequest`)
One row per request from the in-app page or the public form (`src/features/requests`, see ARCHITECTURE.md "Feature requests"): `kind` and `status` (default `new`) are the lists in `validations.ts`, stored as text; `message` plain text; `email` where to reply; `userId` nullable, `onDelete: SetNull` (deleting an account keeps its requests, unlinked); `page` where it was sent from. No IP (the privacy notice says it isn't stored). Indexes: (createdAt) for the owner's list, (userId) for her own.

## Synced profile and choices (`UserProfile`, `UserChoices`)
One row per signed-in user (`userId` is the key, cascade on account delete): the Decide profile and the Choices lists as Zod-validated JSON (`profileSchema`, `choicesSchema`; at most 400 KB), with the `updatedAt` the save action set. `src/app/decide/sync-actions.ts` saves only when the device sends the `updatedAt` it last saw, else returns the server copy; `components/account-sync.tsx` then merges (`lib/account-sync.ts`: the newer copy wins, every choice only in the other is appended, never lost) and saves again. Signed out, both stay in localStorage only. Migration `20261119000000_user_sync`.

## Funnel and the multiple-account guard (`User.signupAid`, `User.signupIpHash`, `Session.aid`, `Session.ipHash`, `FunnelEvent`, `ErrorGroup`)
The sign-up device (`seatora_aid`) and HMAC-SHA256 of the IP (16 hex characters, keyed by `SITE_ACCESS_SECRET`; never the raw IP) on the account (indexed: the per-device sign-up cap and the admin's possible duplicates) and on each session; the two tables above. Migration `20261125000000_funnel_guard`; lockdown after it on Supabase. Details: [FUNNEL.md](FUNNEL.md).

## Payments (`Payment`)
One row per Razorpay order (docs/PAYMENTS.md): `plan`, `amount` (paise, from `PLANS` on the server, less the referral discount), `listAmount` (the price before it), `discount` (CHECK amount = listAmount − discount), `referrerId` (FK SET NULL, indexed), `couponId` (FK SET NULL; migration `20261124500000_coupons`), `currency`, `razorpayOrderId` (unique; the order's receipt is our `id`; null only for a ₹0 coupon row, a CHECK), `razorpayPaymentId` (unique, set when paid), `status` (created, paid, failed; a CHECK constraint), `paidAt`. A paid row is the record of a Season Pass. Index (userId). Cascades on account delete.

## Referrals (`User.referralCode`, `User.referredById`, `User.payoutUpi`, `ReferralEarning`)
`referralCode` (unique; 6–8 of 23456789ABCDEFGHJKMNPQRSTUVWXYZ, a CHECK), `referredById` (FK to User, SET NULL, indexed, CHECK ≠ id), `payoutUpi`; the Payment columns above and `ReferralEarning`. Migration `20261124000000_referrals`; lockdown after it on Supabase. Details: [REFERRALS.md](REFERRALS.md).
## Ask Seatora (`AskLog`, `AskReport`, `AskConversation`, `AskMessage`, `AskPreference`)
Owner-only assistant (docs/ASK_SEATORA.md). All cascade on account delete.
- `AskLog`: one row per run of a turn (a long answer can take several runs), written when it starts (`outcome` "started") and finished with `model`, `effort`, input / output / cache-read / cache-write tokens, `tools` (names), `rounds`, `latencyMs`, `outcome` (ok, partial, refusal, max_rounds, stopped, rate_limited, error), `conversationId`, the answer check's `checkPassed` / `checkFailed`, `corrected`, and `timing` (JSON: modelMs, toolMs, checkMs, firstTextMs, segment). The daily token budget sums input + output + cache writes since 00:00 UTC. Never message text or names. Index (userId, createdAt).
- `AskConversation` (title = her first question, 80 characters; `updatedAt` = last activity; deleted after 30 days) and `AskMessage` (one row per question, role user, and per answer, role assistant; unique (conversationId, requestId, role) makes a repeated request a no-op). The answer row is the turn: `status` (streaming, checkpoint, done, partial, error, stopped), `content` (saved every 2 s while it streams), `thinking` (deep analysis), `segment` (the run it is on), `checkpoint` (JSON, agent.ts Checkpoint: the model messages after the last finished round, dropped when the turn ends) and `phase` (what it is doing now). This holds her questions and the answers (which can include names from residents_at): her own chats, read only by her account.
- `AskPreference`: (userId, key) → value, the preferences she asked it to remember (features/ask/prefs.ts keys).
- `AskReport`: a plan report `create_report` saved: `title` and `json` (`features/ask/reports.ts` reportSchema: profile, summary, ordered choices with their facts at the time, residents counts, risks, sources). Shown at `/decide/ask/report/<id>` to its own account only. Index (userId, createdAt).
